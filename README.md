# CinemaRecommender

Веб-приложение, которое подбирает фильмы, сериалы и мультфильмы по настроению, жанру и типу.

- **Каталог** (`/`) и **страница фильма** (`/movies/{id}`).
- **Подбор** (`/recommend`): за совпадение настроения фильм получает +3 балла, жанра +2, типа +1.
  Показываются первые 10 фильмов с баллом больше нуля; при равных баллах выше фильм с более высоким рейтингом.
- **Админка** (`/admin`): добавление, изменение и удаление фильмов, жанров и настроений.
  Все страницы читают данные из базы при каждом запросе, поэтому изменения видны сразу.
- **Модель на Weka** по описанию и жанрам предлагает в админке одно-два самых вероятных настроения.
- **Чат** (`/chat`): пользователь пишет обычной фразой («устал после работы, хочу мультик»),
  бот определяет настроение, жанр и тип и предлагает 5 фильмов. Для чата обучена отдельная модель.

## Стек

Java 21, Spring Boot 3.5 (Web, Data JPA, Thymeleaf, Validation), PostgreSQL 16, Flyway, Maven, Bootstrap 5, Weka 3.8.

## Что нужно установить

- **JDK 21 или новее** (на более старых JDK проект не соберётся). Переменная `JAVA_HOME` должна указывать на JDK.
- **Docker Desktop** — для базы PostgreSQL. Можно и без Docker, если PostgreSQL уже установлен (см. ниже).
- Maven ставить не нужно: в проекте есть Maven Wrapper (`mvnw` / `mvnw.cmd`).

## Запуск

### 1. Логин и пароль к базе

Создайте в корне проекта файл `.env` (он не попадает в git):

```
DB_USERNAME=postgres
DB_PASSWORD=postgres
```

Приложение берёт логин и пароль из переменных окружения `DB_USERNAME` и `DB_PASSWORD`.
Можно также задать `DB_HOST` и `DB_PORT` (по умолчанию `localhost:5432`).

### 2. База данных

```bash
docker compose up -d
```

Docker поднимет PostgreSQL с пустой базой `cinerec`, взяв логин и пароль из `.env`.
Таблицы и начальные данные (60 фильмов) создаст само приложение при первом запуске — через Flyway.

> Если PostgreSQL установлен без Docker, создайте базу `cinerec` вручную (`CREATE DATABASE cinerec;`).

### 3. Обучение моделей (один раз)

```bash
./mvnw compile exec:java
```

Одна команда обучает обе модели и выводит их точность:

- модель подсказок для админки: `ml/training-data.csv` → `ml/mood-model.model`;
- модель для чата: `ml/chat-training-data.csv` → `ml/chat-model.model`.

Занимает около 30 секунд. Без этого шага приложение работает,
но кнопка подсказки настроения в админке неактивна, а чат сообщает, что модель не обучена.

### 4. Запуск приложения

Переменные окружения нужно задать в той же консоли, где запускается приложение.

PowerShell (Windows):

```powershell
$env:DB_USERNAME="postgres"; $env:DB_PASSWORD="postgres"
.\mvnw.cmd spring-boot:run
```

Git Bash / Linux / macOS:

```bash
export DB_USERNAME=postgres DB_PASSWORD=postgres
./mvnw spring-boot:run
```

Откройте <http://localhost:8080>.

**Из IntelliJ IDEA:** запустите `CinemaRecommenderApplication`, предварительно указав в
Run Configuration → Environment variables: `DB_USERNAME=postgres;DB_PASSWORD=postgres`.

### Тесты

```bash
./mvnw test
```

Тесты бывают трёх видов:

- **Логика** (`RecommendationServiceTest`, `ChatServiceTest`) — правила подбора и разбор сообщений чат-бота.
  База и модели заменены заглушками (Mockito).
- **Контроллеры** (`*ControllerTest`, `@WebMvcTest`) — HTTP-уровень без базы: JSON чата вместе
  с контекстом, проверка формы фильма в админке, пустые и повторяющиеся названия жанров, форма подбора.
- **Интеграционные** (`DatabaseIntegrationTest`) — всё приложение на настоящем PostgreSQL 16, который
  Testcontainers поднимает в Docker: миграции Flyway, соответствие сущностей схеме, начальные данные,
  каскадное удаление жанра, страницы и чат на реальных данных. Нужен запущенный Docker;
  **без Docker эти тесты пропускаются** (в отчёте — Skipped), остальные работают как обычно.
  Рабочая база `cinerec-db` не затрагивается: для тестов создаётся отдельный временный контейнер.

## Структура проекта

```
src/main/java/com/example/cinerec/
├── entity/          сущности: Movie, MovieType, Genre, Mood

├── service/         RecommendationService — подбор по баллам
├── chat/            ChatService — логика бота; ChatReply, ChatMovie — ответ бота
├── controller/      каталог, страница фильма, форма подбора, чат (ChatController)
│   └── admin/       админка: фильмы, жанры, настроения
├── form/            MovieForm — данные формы фильма с проверками
└── ml/              модели настроений:
                     MoodModel (общие настройки), TrainModels (обучение обеих моделей),
                     TrainMoodModel и TrainChatModel (обучение каждой),
                     MoodPredictor (подсказки в админке), ChatMoodPredictor (настроение в чате)
src/main/resources/
├── db/migration/    V1__schema.sql — таблицы, V2__data.sql — начальные данные
├── templates/       страницы Thymeleaf
├── static/js/       chat.js — отправка сообщений чата без перезагрузки страницы
└── application.properties
ml/training-data.csv обучающий набор для админки: 242 фильма (название;настроение;жанры;описание)
ml/chat-training-data.csv  обучающий набор для чата: 600 фраз (настроение;фраза)
docker-compose.yml   PostgreSQL для разработки
```

## База данных

Таблицы: `movie` (название, год, описание, постер, рейтинг, тип), `type`, `genre`, `mood`
и связи многие-ко-многим `movie_genre`, `movie_mood`. При удалении жанра или настроения
его связи с фильмами удаляются автоматически (`ON DELETE CASCADE`).

Скрипты из `db/migration` выполняет Flyway — каждый ровно один раз, поэтому изменения,
сделанные в админке, при перезапуске не теряются. Чтобы вернуть базу к начальному состоянию:

```bash
docker compose down -v   # удалит контейнер вместе с данными
docker compose up -d
```

Постеров в начальных данных нет — вместо них показывается заглушка. Ссылку на постер можно добавить в админке.

## Модель настроений для админки

- **Данные:** 242 фильма, примерно по 40 на каждое из шести настроений. Описания написаны своими словами.
  60 из них — фильмы из базы (с их главным настроением). Список настроений берётся из файла, а не из кода.
- **Признаки:** описание + жанры превращаются в числа с помощью `StringToWordVector`:
  считается, сколько раз встречается каждый кусочек текста из 3–5 букв (символьные n-граммы).
  Кусочки вместо целых слов помогают с русскими окончаниями.
- **Классификатор:** SMO (метод опорных векторов) с калибровкой вероятностей.
  Он показал лучший результат при сравнении с наивным байесовским классификатором и с разбиением на целые слова.
- **Проверка:**
  - тестовая часть: данные делятся на обучающую (80%) и тестовую (20%) части с равной долей каждого настроения.
    На тестовых 49 фильмах модель угадывает настроение в 53% случаев, а правильное настроение
    попадает в два самых вероятных в 86% случаев (при случайном угадывании было бы ~17% и ~33%);
  - перекрёстная проверка на 10 частях: модель 10 раз учится на 9/10 данных и проверяется на оставшейся 1/10,
    так что в проверке побывает каждый фильм. Точность — 59%. Этот результат надёжнее, чем одна тестовая часть.

  Чаще всего модель путает близкие по смыслу пары: «напряжённое» и «мрачное», «уютное» и «весёлое».
  После проверки итоговая модель обучается на всех данных.
- **В админке:** кнопка «Подсказать по описанию» в форме фильма отмечает самое вероятное настроение
  и второе, если его вероятность не меньше половины первого. Админ проверяет отметки и сохраняет фильм.
  Если предложенного настроения нет в справочнике (его переименовали или удалили), админка пишет об этом.

## Модель настроений для чата

Модель подсказок обучена на описаниях сюжетов и плохо понимает фразы пользователей:
например, «хочу посмеяться» она относит к «мрачному». Поэтому для чата обучена отдельная модель.

- **Данные:** `ml/chat-training-data.csv`, 600 фраз, по 100 на каждое настроение: короткие («хочу поплакать»),
  разговорные, с опечатками, с описанием ситуации («устал после работы»).
  Названия настроений в самих фразах встречаются редко (в 14 фразах из 600). Список настроений берётся из файла.
  Сначала набор был из 360 фраз (по 60 на настроение); затем добавлено по 40 фраз на настроение,
  в основном для пар, которые модель путала: «напряжённое ↔ мрачное», «грустное ↔ уютное / вдохновляющее».
- **Откуда фразы:** написаны специально для этого проекта с помощью ИИ-ассистента по правилам выше.
  Это не реальные сообщения пользователей, поэтому на живых сообщениях точность может отличаться.
- **Устройство:** то же, что у модели для админки (`MoodModel`: символьные n-граммы + SMO).
- **Проверка:** перекрёстная проверка на 10 частях. Точность — 69% (на первых 360 фразах было 56%,
  наугад было бы ~17%). Лучше всего распознаётся «весёлое» (82 фразы из 100),
  чаще всего путаются «напряжённое» и «мрачное».
- **Порог уверенности 0.5.** Если модель уверена меньше чем на 50%, бот считает настроение неопределённым.
  Порог выбран по таблице, которую печатает обучение (сейчас, на 600 фразах):

  | Порог | Настроение определено | Из них верно |
  |-------|-----------------------|--------------|
  | 0.3   | 95% фраз              | 71%          |
  | 0.4   | 79% фраз              | 77%          |
  | 0.5   | 65% фраз              | 84%          |
  | 0.6   | 52% фраз              | 89%          |

  При 0.5 бот определяет настроение примерно в двух фразах из трёх и в этих случаях прав в 84%.
  При 0.4 он определяет больше, но чаще ошибается; при 0.6 и выше переспрашивает почти в половине случаев.
  Лучше переспросить, чем уверенно подобрать не то. (На первом наборе из 360 фраз был выбран порог 0.4:
  при 0.5 там настроение определялось меньше чем в половине фраз.)

## Чат-бот

Страница `/chat`. Сообщение отправляется без перезагрузки страницы: скрипт `chat.js` вызывает
`POST /api/chat` и получает ответ в JSON. История переписки хранится только на странице.

Как бот разбирает сообщение (`ChatService`):

1. На приветствие и «спасибо» отвечает коротко, без подбора.
2. **Настроение** определяет модель для чата (с порогом уверенности 0.5).
3. **Жанр и тип** ищет среди названий из таблиц `genre` и `type`. Для жанров и типов из начальных данных
   есть словарь начал слов (`KEYWORDS`): «фантастический» → фантастика, «мультик» → мультфильм,
   «фильм ужасов» → ужасы, а «ужасно устал» жанром не считается. Новые названия из админки ищутся
   по основе слова — названию без двух последних букв, но не короче 4 букв («вестерн» → «весте»).
   Справочники читаются из базы при каждом сообщении.
   **Отрицание** перед жанром или типом («только не ужасы», «без мультиков», «не хочу сериал»)
   исключает такие фильмы из подбора. Действует, только если «не», «без» или «кроме» стоит прямо
   перед словом или перед глаголом вроде «хочу» — в «не грустную комедию» комедия остаётся нужной.
   Сообщение из одних запретов модели не передаётся: по названию жанра («мелодрамы») она уверенно
   угадала бы настроение, которого в сообщении нет.
   **Несколько жанров и типов** («комедию или мелодраму», «фильм или сериал») учитываются все:
   баллы за жанр фильм получает, если у него есть любой из названных жанров, за тип — если он любого
   из названных типов (баллы не суммируются, поэтому максимум по-прежнему 6).
   **Годы выпуска** (`YearRange`) — фильтр, а не баллы: «из 90-х», «1980-х», «нулевых», «после 2010»,
   «с 1990 по 1999», «до 2000», «фильм 1994 года». «Новое» — последние 10 лет каталога, «старое» —
   на 30 лет и более старше самого нового фильма в базе (отсчёт от каталога, а не от текущего года,
   иначе при каталоге до 2020 года «новых» фильмов не нашлось бы). «На новый год» годом не считается.
   Если указаны только годы («что-нибудь из 90-х»), бот показывает все фильмы этих лет по рейтингу.
4. Найденное настроение ищет в таблице `mood` по названию. Если его там нет, подбирает только по жанру и типу
   и пишет об этом.
5. Фильмы подбирает тот же `RecommendationService`, что и форма подбора; показывает первые 5.
6. Отвечает по шаблону: что понял (настроение с процентом уверенности, жанр, тип, что исключить)
   и карточки фильмов.

**Контекст разговора.** Вместе с ответом бот отдаёт условия подбора и id уже показанных фильмов
(`ChatContext`), а страница присылает их со следующим сообщением. На сервере ничего не хранится.
- «ещё», «покажи другие», «а что-нибудь ещё есть?» — следующие 5 фильмов по тем же условиям без повторов,
  пока подходящие не закончатся (в чате нет ограничения в 10 фильмов, как в форме подбора);
- «а сериал», «лучше мультик», «а теперь комедию», «только не ужасы», «из 90-х» — уточнение: новые условия
  заменяют прежние, остальные (например, настроение) сохраняются;
- сообщение без этих слов («посоветуй ужастик») — новый подбор с нуля.
   Если не понял ничего — просит описать иначе и приводит примеры.

Если модель для чата не обучена, чат сообщает об этом и подсказывает команду обучения.

Чтобы дообучить модели, добавьте строки в нужный CSV-файл, снова выполните
`./mvnw compile exec:java` и перезапустите приложение.

## Ограничения

- Админка не защищена паролем (Spring Security по условию задания не используется).
- Рейтинги фильмов в начальных данных приблизительные.
- Слово «фильм» в сообщении чата считается типом «фильм», поэтому в ответе на «посоветуй фильм…»
  фильмы получают +1 балл и оказываются выше сериалов и мультфильмов.
